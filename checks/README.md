# Проверки платформы

Сценарии, которые прогоняются на живом PostgreSQL и собранном приложении.
Не unit-тесты: каждый шаг — настоящий HTTP-запрос или настоящий клик в Chrome.

## Что нужно

1. PostgreSQL с применённой схемой (`npm run db:push` или `scripts/init-db.sql`).
2. Собранное и запущенное приложение (`npm run build`, `npm start`).
3. Переменные окружения тестового стенда.

## Запуск

```powershell
$env:PSQL = "C:\Program Files\PostgreSQL\16\bin\psql.exe"   # или просто psql из PATH
$env:VERIFY_DB = "app_db"
$env:BASE_URL = "http://127.0.0.1:3100"
$env:SESSION_SECRET = "<из .env>"
$env:ADMIN_PASSWORD = "<из .env>"

powershell -File checks/run-all.ps1
```

`run-all.ps1` перед каждым сценарием заливает `checks/seed.sql`, поэтому данные
в базе не важны — они перезаписываются.

## Что покрыто

| Файл | Что проверяет |
| --- | --- |
| `e2e.js` | страницы и доступ: счётчики, деньги, изоляция чужого задания, отчёт, редирект, 404 |
| `test-login.js` | вход по паролю через настоящую форму, выход стирает cookie |
| `test-csrf.js` | запрос с чужого `Origin` отклонён |
| `test-mutation.js` | ответ исполнителя сохраняется, принятый переписать нельзя |
| `test-accept.js` | приёмка владельцем, пересчёт маржи |
| `test-take-rate.js` | взятие задания вторым исполнителем, оценка ставится один раз |
| `test-chat-market.js` | чат у всех трёх сторон, чужое задание недоступно, услуги на бирже |
| `check-constraints.sql` | триггер оценок, уникальные индексы, обязательная ссылка на отзыв |
| `check-chat-guard.sql` | историю чата нельзя изменить или удалить |

Браузерные сценарии (`browser-test.js`, `browser-chat.js`) запускаются отдельно:
нужен Chrome с `--remote-debugging-port` и адрес CDP внутри файла.

## Важно про данные

`seed.sql` делает `TRUNCATE ... RESTART IDENTITY CASCADE`. Запускать только на
тестовой базе. На рабочей — потеряете заказчиков и отзывы.
