## 2. Что за бизнес

Управление репутацией заведений (сеть клиник — реальный пример).

- Заказчик платит за ответы на отзывы: ориентир **650 ₽ за ответ**.
- Исполнитель получает **250 ₽ за ответ**. Маржа 400 ₽ с позиции.
- Цены не единые: зависят от площадки (Яндекс.Карты, 2ГИС, Google) и условий заказчика.
  Поэтому ставки — поля задания, а не константы в коде.
- Отзывы вносит владелец руками: текст + обязательная ссылка на источник.
- **Накрутка закрыта навсегда**: никаких фейковых, покупных или написанных нами отзывов.
  Только ответы на реальные отзывы реальных людей.

## 4. Что сделано и проверено

### Платформа (главное)

Три кабинета:

- **`/admin`** — владелец, вход по паролю `ADMIN_PASSWORD`.
  Заказчики → филиалы → отзывы → задания → проверка позиций → оценки, деньги, маржа.
- **`/work/<token>`** — исполнитель по постоянной ссылке. До взятия видит только сводку
  (филиалов, текстов, ставка). Тексты открываются после взятия. Форма ответа, чат, услуги
  на бирже.
- **`/r/<token>`** — заказчик по постоянной ссылке. Прогресс, чат, отчёт
  `/r/<token>/report` в формате «филиал → ссылка на карту → отзывы с ответами» + печать.

Модель данных: `clients → venues → reviews → task_items`, рядом `workers`, `tasks`,
`ratings`, `messages`, `worker_services`.

Гарантии в базе, а не в коде:

- Триггер запрещает UPDATE и DELETE в `ratings` и `messages`.
- Уникальный индекс: одна оценка на задание от каждой стороны.
- Дубль позиции в задании невозможен, отзыв без ссылки на источник невозможен.
- `db:push` применяет триггеры через `scripts/apply-guards.mjs`.

### Проверено

- `typecheck`, `lint`, `build` — exit 0, 26 маршрутов.
- `checks/run-all.ps1` — 7 сценариев на живом PostgreSQL, каждый с чистых данных.
- 9 SQL-проверок ограничений.
- Браузер: настоящий Chrome через DevTools Protocol — вход формой, взятие задания,
  отчёт, чат между всеми сторонами, отсутствие горизонтального скролла на 390 px.
- Резервные копии: дамп → удаление → восстановление, триггеры возвращаются с данными.

### Что чинилось по дороге (чтобы не наступить снова)

- `npm start` не читал `.env` → падало на `SESSION_SECRET`. Исправлено:
  `node --env-file-if-exists=.env`.
- `drizzle-kit push` не создаёт триггеры → оценку можно было переписать UPDATE-ом.
  Теперь `db:push` вызывает `apply-guards.mjs`.
- `docker-compose` не передавал `ADMIN_PASSWORD` → кабинет не открывался бы на сервере.
- `init-db.sql` был сломан (слипшийся комментарий съел `CREATE TABLE ratings`) —
  чистая установка падала.
- Деплой-скрипты полагались на `docker-entrypoint-initdb.d`, который работает только
  на пустом томе → при обновлении новые таблицы не появлялись.
- Принятый ответ можно было переписать из кабинета исполнителя.
- Метрика «с первого раза» считалась неверно (позиция с возвратом попадала в числитель).
- `guard()` глушил все ошибки БД, авария выглядела как «работы нет».

## 5. Чего НЕ сделано (честно)

### Биржа задач — готова частично

Владелец спросил прямо. Ответ: **это доска объявлений, а не маркетплейс**.

Что есть:

- Исполнитель выставляет услуги: площадка, название, ставка, описание; может скрыть.
- Владелец видит их в `/admin/workers` и в разделе «Биржа».
- Исполнитель видит все свободные задания и может взять любое.

Чего нет:

- **Нет рейтинг-гейта.** В `AGENTS.md` записано решение: «низкий рейтинг — задание
  берётся с подтверждением владельца». В коде этого нет: `takeTaskAction` проверяет
  только «свободно» и «не заблокирован».
- **Нет сопоставления.** Задания не сортируются под услуги исполнителя, площадка не
  учитывается.
- **Исполнитель не видит рейтинг заказчика** до взятия задания, хотя решение о
  видимости обеих сторон принято.
- **Нет заявок.** Исполнитель может только взять задание целиком, не подать заявку.

### Не опубликовано

Платформа работает **локально**: `http://localhost:3000`, база `ratify` на локальном
PostgreSQL. Публичного адреса нет.

Причина не в коде: **нет сервера и домена**. Всё для деплоя готово (`DEPLOY.md`,
`scripts/bootstrap-server.sh`), но нужны IP, домен и доступ по SSH.

Следствие: ссылки `/work/<token>` и `/r/<token>` сейчас работают только на машине
владельца. Отправить заказчику такую ссылку нельзя.

### Прочее

- Docker-образ ни разу не собирался: Docker на машине нет. Compose и Dockerfile
  проверены чтением и запуском скриптов, но не сборкой.
- Печать отчёта в PDF глазами не проверялась.
- Telegram-бот (средний приоритет) не начат: есть только исходящие уведомления о заявках.
- Google Таблицы не начаты.
- Сайт-витрина не трогался, кроме обёртки `SiteChrome` (скрывает шапку в кабинетах).
  Это соответствует приоритету владельца: витрина — низкий.
- Тестов на мутации в CI нет; проверки запускаются вручную.

- Пуш работает без ввода пароля: доступ закеширован в Windows Credential Manager.
- `git` в системе не установлен. Используется портативный:
  `.tools\git\cmd\git.exe` (в git не попадает).

## 7. Как запустить локально

```powershell
# база (портативный PostgreSQL в .tools)
.tools\pg\pgsql\bin\pg_ctl.exe -D .tools\pgdata -l .tools\pg.log `
  -o "-p 5432 -c listen_addresses=127.0.0.1" start

# схема
$env:DATABASE_URL = "postgresql://postgres@127.0.0.1:5432/ratify"
npm run db:push

# сборка и запуск
npm run build
npm start          # читает .env, поднимает порт 3000
```

Открыть `http://localhost:3000/admin`, войти паролем из `.env`.

Запуск проверок — `checks/README.md`.

1. **Опубликовать.** Нужны сервер, домен, SSH-доступ. Пошагово — `DEPLOY.md`.
   После запуска: `/api/health` отдаёт `{"ok":true}`, вход в `/admin` работает.

3. **Доделать биржу до конца** (см. раздел 5):

   - сопоставление заданий с услугами (площадка + ставка), пометка «подходит»;
   - исполнитель видит рейтинг заказчика до взятия;
   - уведомление владельцу о заявке на взятие.
4. **Первый реальный заказчик.** Завести одну сеть, одну пачку отзывов, одного
   исполнителя. Пройти полный цикл: задание → ответы → приёмка → отчёт клиенту.
   Это покажет, чего не хватает, точнее любого плана.
5. Только после этого — Telegram-бот и Google Таблицы (средний приоритет).

## 9. Правила, которые нельзя нарушать

Из `AGENTS.md`, раздел 2 — нарушение это дефект, а не стилистика:

- Не выдумывать факты, цифры, клиентов, кейсы, отзывы.
- Не предлагать накрутку: фейковые и покупные отзывы, имитацию аккаунтов, накрутку
  поведенческих факторов. Работаем только с реальными отзывами реальных людей.
- Новые цены — только по прямому слову владельца.
- Контакты — только из `src/lib/contacts.ts`.
- Секреты — только в `.env`.
- Не выдавать желаемое за сделанное: не проверил — сказать, что не проверил.
- После правок: `npm run typecheck`, `npm run lint`, для крупных — `npm run build`.
- Всё решённое дописывать в `AGENTS.md`, раздел 14, с датой.
