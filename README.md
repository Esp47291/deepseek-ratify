# ratify

Два слоя в одном приложении:

1. **Сайт агентства** — Яндекс.Директ, SEO, аудит сайта и продукта, ведение карточки в
   Яндекс.Бизнесе. Посетитель оставляет заявку, она сохраняется в PostgreSQL и приходит в
   Telegram.
2. **Платформа управления репутацией** — задания на ответы к реальным отзывам: владелец
   вносит отзывы, исполнитель отвечает по форме, заказчик видит прогресс и отчёт.

**Стек:** Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4, Framer Motion,
PostgreSQL 16, Drizzle ORM.

## Запуск на своём компьютере

Нужен Node.js 22 или новее (`node -v`).

```powershell
Copy-Item .env.example .env
npm install
npm run dev
```

Сайт откроется на http://localhost:3000.

Без базы данных сайт работает полностью, но заявки из форм не сохраняются и кабинеты
платформы показывают пустые состояния. Чтобы всё заработало, запустите PostgreSQL
(например, через Docker) и примените схему:

```powershell
docker run -d --name ratify-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=app_db -p 5432:5432 postgres:16-alpine
npm run db:push
```

Либо один раз выполнить идемпотентный скрипт: `psql "$DATABASE_URL" -f scripts/init-db.sql`.

`npm run db:push` применяет не только таблицы, но и гарантии в базе: триггер, который
запрещает менять и удалять оценки, и уникальный индекс «одна оценка на задание». Без них
рейтинг можно было бы переписать SQL-запросом. Повторно применить только гарантии —
`npm run db:guards`.

Уведомления в Telegram включаются переменными `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.

## Платформа: кабинеты

| Адрес | Кто заходит | Как |
| --- | --- | --- |
| `/admin` | владелец | пароль `ADMIN_PASSWORD`, сессия подписана `SESSION_SECRET` |
| `/work/<token>` | исполнитель | постоянная ссылка-токен из кабинета владельца |
| `/r/<token>` | заказчик | постоянная ссылка-токен, без пароля |
| `/r/<token>/report` | заказчик | отчёт «филиал → ссылка → отзывы с ответами» |

Как это работает:

- Владелец создаёт заказчика и его филиалы (адрес + ссылка на карточку на картах).
- Вносит отзывы **вручную**: текст и обязательная ссылка на источник.
- Создаёт задание — пачку отзывов с ценой заказчику и ставкой исполнителю за позицию.
- Исполнитель до взятия задания видит только сводку (филиалов, текстов, ставка), тексты
  открываются после взятия.
- Исполнитель отвечает по форме; владелец принимает или возвращает на доработку.
- Заказчик открывает свой кабинет и отчёт — без переписки в мессенджерах.

Рейтинги считаются из событий и не хранятся числом: средняя оценка владельца, доля
принятых с первого раза, объём принятых позиций, число завершённых заданий. Оценки в
таблице `ratings` нельзя изменить или удалить — это держит триггер в базе.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Режим разработки на http://localhost:3000 |
| `npm run build` | Сборка для продакшена (нужен доступ к Google Fonts) |
| `npm start` | Запуск собранного сайта |
| `npm run typecheck` | Проверка типов |
| `npm run lint` | Проверка кода |
| `npm run db:push` | Создать или обновить таблицы и применить гарантии в БД |
| `npm run db:guards` | Применить только гарантии (триггер оценок), идемпотентно |

## Структура

- `src/app/` — страницы сайта, API заявок `api/leads`, кабинеты `admin`, `work`, `r`.
- `src/components/` — шапка с мега-меню, подвал, формы, калькулятор, SVG-иллюстрации,
  `components/platform/` — общая рамка кабинетов.
- `src/lib/services-data.ts` — услуги, этапы работы и FAQ: всё меню и страницы услуг строятся отсюда.
- `src/lib/contacts.ts` — телефон, email и мессенджеры.
- `src/lib/platform.ts` — деньги и рейтинги: чистые функции без БД.
- `src/lib/auth.ts` — сессия владельца и токены кабинетов.
- `src/db/schema.ts` — все таблицы: заявки и платформа.
- `src/app/globals.css` — дизайн-система: цвета, кнопки, карточки, типографика.
